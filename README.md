# dsh-token-ring

给 **DSH**（DeepSeekRuntime）加三个会动的环：**Token 花在哪、花了多少钱、模型各占多少**。

装在设置页里，打开 **设置 → 用量** 就是全部内容。

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  TOKEN 构成   │  │  花费 / 省下  │  │   模型占比    │
│    ╭────╮    │  │    ╭────╮    │  │    ╭────╮    │
│   │ 101M │   │  │   │ ¥6.7 │   │  │   │  1   │   │
│    ╰────╯    │  │    ╰────╯    │  │    ╰────╯    │
│  ● 缓存读 92% │  │  ● 实际花费  │  │  ● 模型名     │
│  ● 输入   6%  │  │  ● 缓存省下  │  │              │
│  ● 输出   2%  │  │              │  │              │
└──────────────┘  └──────────────┘  └──────────────┘
```

## 三个环

| 环 | 看什么 |
|---|---|
| **Token 构成** | 缓存读 / 未缓存输入 / 输出 / 缓存写，四段占比，环心是总量 |
| **花费 / 省下** | 绿色是真正花掉的钱，灰色是缓存替你省下的；环心是金额，副标是缓存命中率 |
| **模型占比** | 每个用过的模型一段，环心是模型个数 |

## 时间线

三个环下面还有一张时间线图，按 **小时 / 天 / 月** 三档聚合，堆叠柱状图，每根柱子按 token 类型分色。

它跟上面三个环**用的不是一份数据**：

| | 三个环 | 时间线 |
|---|---|---|
| 数据源 | `projcache` 的会话累计值 | `session.v4.jsonl.zstd` 里**每次 LLM 调用** |
| 时间维度 | 只有会话创建时间 | 每次调用自己的时间戳 |
| 模型归属 | 会话的最后一次选择 | **每次调用实际用的模型** |

所以时间线能画出真实趋势，而圆环告诉你总量。

首次扫描会走全部会话日志（60 个文件 / 112 MB 约 3.5 秒），结果按 `mtime + size` 缓存在
`~/.dsh/token-usage/timeline-cache.json`，之后只重扫变过的文件。

## 交互

环不是摆设，每一段都能指：

- **悬停** → 环心就地换成那一段的数字（数量、占比、金额），其余段变暗、当前段加粗发光
- **点击** → 锁定，把鼠标移开也不会丢；再点一次取消，或点另一段直接换
- **点空白处** → 解锁
- 切时间范围会清掉锁定

图例也能点，跟环上的段是同一份状态。

### Q 弹

- 圆环入场从 84% 缩到 103% 再落回，带 -7° 旋转
- 悬停加粗用超冲曲线，不是线性的
- 按下瞬间鼓到 17px
- 环心数字三段回弹（68% → 113% → 96% → 100%）
- 图例色块悬停放 1.55 倍

全部走同一条 `cubic-bezier(.34, 1.56, .64, 1)`。

## 时间范围

右上角五个档：**全部 / 90 天 / 30 天 / 7 天 / 今天**。

**默认「今天」** —— 打开就是今天用了多少，想看历史再点别的。

## 计数法

大数字用 K / M / B / T：

| 数值 | 显示 |
|---|---|
| 19.6 亿 | `1.96B` |
| 5285 万 | `52.9M` |
| 895 万 | `9.0M` |
| 8.4 万 | `84.2K` |
| 1173 | `1,173` |

千位以下保持原样带千分位，不硬凑成 `0.5K`。K/M 一位小数，B/T 两位。
临界值会进位（`999,999` → `1.0M`，不会显示成 `1000.0K`）。

## 数据从哪来

只读 DSH 的会话投影缓存，**一个字节都不写**：

```
~/.dsh/storages/session_projcache/sessions/session-*.json
  record.rows.tokenUsage.val.totals           四类 token 累计
  record.rows.modelSelection.val.lastUsed     该会话用的模型
  record.rows.sessionStats.val.turns          轮数
  record.identity.createdAt / cwd             时间与项目
```

所以**装之前的历史也能统计**，不用等数据重新积累。

服务端有 20 秒聚合缓存（`STATS_TTL`），连续刷新不会反复读盘。

## 花费怎么算

优先读 `~/.dsh/token-usage/pricing.ccsa.json`（如果装过带定价表的插件，里面有 223 个模型的真实价目，人民币）；
读不到就用内置兜底表（DeepSeek / GLM 常用档）。

模型名带地区前缀（`cn:`、`us:` 之类）会自动剥掉再匹配。表里查不到的模型按 flash 档计价——宁可低估，不虚报。

```
花费 = 未缓存输入/1e6 × 输入价
     + 输出/1e6     × 输出价
     + 缓存读/1e6   × 缓存读价
     + 缓存写/1e6   × 缓存写价
```

「缓存省下」= 缓存读的那些 token，如果按未缓存输入价算要多花多少。

## 接口

```
GET /dsh-token-ring/api/stats?range=all|90d|30d|7d|today
GET /dsh-token-ring/api/timeline?unit=hour|day|month&limit=N
```

`stats` 返回：

```json
{
  "ok": true,
  "range": "today",
  "currency": "RMB",
  "pricingSource": "pricing.ccsa.json",
  "sessionCount": 3,
  "turns": 17,
  "totals": { "input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0, "total": 0 },
  "cost": 0,
  "cacheSaved": 0,
  "cacheHitRate": 0,
  "models": [{ "model": "...", "total": 0, "share": 1, "cost": 0 }]
}
```

只允许回环访问；非回环交给 DSH 的 `connection.requestRejection` 判定，判不了就直接 403。

## 安装

```powershell
cd $env:USERPROFILE\.dsh\profiles\desktop
pnpm add "link:$env:USERPROFILE\.dsh\plugins\dsh-token-ring"
```

再把 `dsh-token-ring` 加进该 profile 的 `dsh.profile.bundles`：

```json
{
  "dsh": {
    "profile": {
      "bundles": ["...", "dsh-token-ring"]
    }
  }
}
```

重启 DSH。

## 已知边界

- **圆环的模型占比按会话归属**：一个会话中途换了模型，全部用量都记在它最后用的那个模型上。
  DSH 的会话缓存只保留 `lastUsed`。想要逐请求精确归属，看**时间线**——它扫的是调用日志，每次调用的模型都对得上。
- **时间线首次扫描慢**：约 3.5 秒（60 个文件 / 112 MB），之后有 mtime+size 缓存，只重扫变过的文件。
- **`cacheWrite` 常为 0**：走缓存写入的接口才会计数，大多数 API 不报这一项。
  环会自动跳过为 0 的段，所以实际渲染的是三段而不是四段——这是正常的。
- **日期口径按本机时区的自然日**。
- **单模型时是完整一圈**：只有一个模型在用时环是满的，不是画错了。
